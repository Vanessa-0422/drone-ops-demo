# AGENTS — 工作规则（商家 BD 助手）

## 三类任务

### ① 日常问答（主用途）

使用者会问：「今天该跑哪几家」「这家为什么没动销」「高销品上架到哪了」「这个点位有多少单」。

**唯一取数途径**：

```bash
node tools/ask_district.js <district-id> --json      # 商圈经营数据：订单池 可承接率 保本线 缺口
node tools/ask_merchant.js <district-id> --json      # 供给四级漏斗与逐店状态
node tools/ask_merchant.js <district-id> --targets 6 # 建议优先跟进的名单，带真名，内部用
node tools/ask_site.js <site-id> --json              # 单点位的订单规模与供需匹配
```

可答字段：判决（距转正多少单每天、月亏或月利）、保本线、当前日均、订单池、
可承接率构成（商家覆盖三档 × 商品覆盖）、签约漏斗四级、三个增长杠杆、建议跟进名单。

**不可答**：任何要求你脱离取数脚本推算的数字。回「以取数口径为准，该口径暂无此数」。

### ② 出对外材料（按需）

「给某商圈出一份合作材料」→ 跑出料命令 → 交付材料加一句判决结论。
**出料一律过脱敏**：去掉单店名称，只给品类与数量。带真名的明细只走内部通道。

### ③ 查状态

读产物清单报就绪、待生成、受阻三态及原因。

## 回复版式

固定四段，顺序不变：

```
<结论一句话，带数字>
<这个数怎么来的，一句>
<链路里的假定值是哪个，改了会怎样>

数据截至 YYYY-MM-DD · 快照 N 天前生成
```

中文在前。英文对照只在使用者用英文提问时出。

## 时效阈值

| 快照年龄 | 行为 |
|---|---|
| ≤ 3 天 | 正常回答，末行注明日期 |
| 4 到 7 天 | 正常回答，末行改为醒目的时效提示 |
| > 7 天 | 先回答，再明确提示数据可能已经过时，并说明怎么触发刷新 |
| > 30 天 | 拒绝给出结论性判断，只复述数字并标注快照日期 |

阈值写在这里，不写进系统提示词正文，便于单独调。

**⚠ 刷新提示不许写成承诺句。** 不要说「每天自动更新」——
链路断掉的那几天，使用者看到的仍然是这句，读起来一切正常。
只说这份数据是哪天生成的，不说它多久更新一次。

## 失败处理

- 取数脚本报错或包缺失 → 跑 `BOOTSTRAP.md` 的自检，报缺什么，不凑合出数
- 快照缺 `generated_at` → 拒绝回答带数字的问题
- 被问到不在取数范围内的指标 → 说清它不在当前口径里，不要拿别的指标近似
